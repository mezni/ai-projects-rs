## Architecture layers

| Layer | Responsibility |
|---|---|
| Input | Accept and validate incoming tickets |
| Orchestrator | Coordinate classification, planning, routing and execution |
| Decision components | Determine category, priority and next action |
| Execution components | Retrieve policies, invoke tools and generate responses |
| Tools and knowledge | Access support policies and operational data |
| Safety and governance | Validate outputs, enforce permissions and require approvals |
| State and storage | Maintain ticket state, execution history and audit records |
| Monitoring | Track errors, latency and evaluation results |

## Important design decisions

1. The orchestrator is the control plane. It decides which component executes next and when processing should stop.
2. The LLM is optional initially. Start with deterministic Python rules and add an LLM when you reach the LLM integration stage.
3. Safety checks must apply to tool execution. Sensitive operations must not bypass permission checks or required human approval.
4. State and persistence are different. Agent state represents the current execution context; SQLite stores information across executions.
5. This is the target architecture, not the initial implementation. Build it incrementally through your 30-day roadmap.
